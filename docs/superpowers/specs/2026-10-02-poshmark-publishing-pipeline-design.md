# Poshmark Publishing Pipeline Design

**Date**: 2026-10-02  
**Status**: Design  
**Parent**: [Poshmark Integration Design](./2026-05-20-poshmark-integration-design.md)

---

## Context

The original Poshmark integration spec (2026-05-20) designed the adapter and SDK but left publishing unimplemented because `POST /vm-rest/posts` (create listing) still needs reverse-engineering via Charles Proxy. This spec designs the full publishing pipeline **pipeline-first**: build every layer except the SDK's `createListing` method now, so that when the endpoint is reverse-engineered, wiring it up is a single SDK addition with no further pipeline changes.

Everything else is ready: `step4a` already generates `platform_fields.poshmark`, `getPoshmarkCreds` exists, `PoshmarkAdapter` handles reads. The pipeline is the gap.

---

## What We're Building

1. **Expanded `platform_fields.poshmark` type** — add all fields Poshmark requires
2. **`step4a` additions** — AI generates colors, style tags, department, subcategory
3. **`POSHMARK_CATEGORY_MAP`** — static TypeScript constant mapping slugs → hex IDs (full tree: 6 departments, 110 categories, 633 subcategories)
4. **`buildUnifiedListingForPoshmark`** — assembles publishing payload from listing + photos
5. **`publishListingToPoshmark`** — orchestrates adapter call + DB update
6. **`POST /api/listings/[id]/post-to-poshmark`** — HTTP trigger route
7. **`PoshmarkAdapter.createListing` stub** — typed `PoshmarkCreatePendingError` instead of `UnsupportedOperationError`

## step4a Changes

**File**: `src/lib/pipeline/step4a-draft-listing.ts`

Add to the AI tool schema output fields:

| New field | Type | Description |
|---|---|---|
| `poshmark_department` | `string` | One of: `Women`, `Men`, `Kids`, `Home`, `Pets`, `Electronics` |
| `poshmark_subcategory` | `string \| null` | Subcategory slug from the category tree (null if none fits) |
| `poshmark_colors` | `string[]` | Up to 2 colors from Poshmark's color set |
| `poshmark_style_tags` | `string[]` | Exactly 3 freeform style/aesthetic tags |

The AI prompt for step4a should include:
- The list of valid departments
- The category tree for the chosen department (injected based on item type, or all departments if ambiguous)
- Poshmark's color options: `["Black", "White", "Gray", "Red", "Pink", "Orange", "Yellow", "Green", "Blue", "Purple", "Brown", "Tan", "Beige", "Gold", "Silver", "Cream", "Nude", "Multicolor"]`

Style tags are freeform — the AI picks 3 that describe the item's aesthetic, era, or style (e.g., "Vintage", "Streetwear", "Y2K", "Minimalist", "Luxury").

The existing `poshmark_title`, `poshmark_description`, `poshmark_category`, `poshmark_size` fields remain; `poshmark_department` and `poshmark_subcategory` are added alongside them. The assembled `platform_fields.poshmark` block also picks up the new fields.

## Poshmark Category Map

**File**: `src/lib/platforms/poshmark-categories.ts`

A static TypeScript constant generated from the scraped category tree (saved at scratchpad during planning). Structure:

```ts
export interface PoshmarkCategoryIds {
  departmentId: string
  categoryId: string
  subcategoryId?: string
}

// Key format: "Department/Category" or "Department/Category/Subcategory"
// All slugs use Poshmark's display-derived slug format (e.g., "Ankle_&_Cropped")
export const POSHMARK_CATEGORY_MAP: Record<string, PoshmarkCategoryIds> = {
  "Women/Jeans": { departmentId: "000e8975d97b4e80ef00a955", categoryId: "001a8975d97b4e80ef00a955" },
  "Women/Jeans/Boot_Cut": { departmentId: "000e8975d97b4e80ef00a955", categoryId: "001a8975d97b4e80ef00a955", subcategoryId: "00909287d97b4e80ef00a955" },
  "Electronics/Cameras": { departmentId: "583c7d134024035188906153", categoryId: "..." },
  // ... all 6 departments × all categories × all subcategories
}

export function lookupPoshmarkCategory(
  department: string,
  category: string,
  subcategory?: string
): PoshmarkCategoryIds {
  const key = subcategory
    ? `${department}/${category}/${subcategory}`
    : `${department}/${category}`
  const ids = POSHMARK_CATEGORY_MAP[key]
  if (!ids) throw new Error(`Unknown Poshmark category: ${key}`)
  return ids
}
```

The full constant is generated from `poshmark_categories.json` (scratchpad file from planning). All 6 departments, 110 categories, 633 subcategories are included. The "Global & Traditional Wear" grouping (no hex ID) is omitted from the map; its children (Ao Dais, Hanboks, etc.) are included as direct category entries under their department.

## Photo Selection

**Logic** (in `publishListingToPoshmark`):

1. Start with all studio-type photos ordered by `display_order`
2. Promote any photo whose `metadata.tags` includes `"auth_card"` or `"authentication"` to the end of the list.
3. Cap at 16 (Poshmark's limit)
4. If `photo_ids` override is passed in the request body, use that ordered list instead (still filtered to studio type, still capped at 16)

The `cover_shot` is the first photo in the final list; `pictures` is the full list.

## `buildUnifiedListingForPoshmark`

**File**: `src/lib/platforms/publish-to-poshmark.ts` (new file)

```ts
export function buildUnifiedListingForPoshmark(
  listing: Listing,
  photos: Photo[]
): { unified: UnifiedListing; poshmarkExtras: PoshmarkListingExtras }
```

**`PoshmarkListingExtras`** (Poshmark-specific fields not in `UnifiedListing`):

```ts
interface PoshmarkListingExtras {
  department: string
  categoryIds: PoshmarkCategoryIds
  colors: string[]
  styleTags: string[]
  originalPriceCents?: number
  minPriceCents?: number
  smartSell: boolean
}
```

**Assembly:**

- `internalId` = `listing.sku`
- `title` from `platform_fields.poshmark.title`
- `description` from `platform_fields.poshmark.description`
- `price` via `resolveFinalPriceCents()` (same helper as eBay)
- `condition` mapped via `POSHMARK_CONDITION_MAP`:

  | Internal `ConditionValue` | Poshmark enum |
  |---|---|
  | `new_with_tags` | `"nwt"` |
  | `new_without_tags` | `"uln"` |
  | `like_new` | `"uln"` |
  | `good` | `"ug"` |
  | `fair` | `"uf"` |
  | `poor` | `"uf"` |

- `brand` from `listing.brand`
- `imageUrls` from selected photos (resolved via `toPublicUrl()`)
- `categoryIds` from `lookupPoshmarkCategory(department, category, subcategory?)`
- `colors` from `platform_fields.poshmark.colors`
- `styleTags` from `platform_fields.poshmark.style_tags`

Throws if `platform_fields.poshmark` is missing, price can't be resolved, or category lookup fails.

## `publishListingToPoshmark`

**File**: same `src/lib/platforms/publish-to-poshmark.ts`

```ts
export async function publishListingToPoshmark(
  supabase: SupabaseClient,
  listing: Listing,
  photos: Photo[],
  adapter: PlatformSDK,
  options: { draft?: boolean; photoIds?: string[] }
): Promise<{ platformId: string; url: string }>
```

Steps:
1. Select photos (see Photo Selection above; respects `options.photoIds` override)
2. `buildUnifiedListingForPoshmark(listing, selectedPhotos)`
3. If `!options.draft`: `adapter.createListing(unified, poshmarkExtras)` — currently throws `PoshmarkCreatePendingError`
4. On success: update `listings` row — `listing_urls` (append poshmark URL), `status: 'published'`, `platform_fields.poshmark.listing_id`
5. Insert `platform_price_events` row (`event_type: 'published'`, `platform: 'poshmark'`)

## HTTP Route

**File**: `src/app/api/listings/[id]/post-to-poshmark/route.ts`

`POST` handler mirrors `post-to-ebay/route.ts`:

1. Auth check
2. Load `listings` row, verify ownership
3. Verify `isPricingGateUnlocked` (same gate as eBay)
4. Validate `platform_fields.poshmark` exists and has required fields (`title`, `description`, `department`, `category`, `size`, `colors`, `style_tags`)
5. `getPoshmarkCreds(user.id)` — returns 401 if not connected
6. Load studio photos ordered by `display_order`
7. Parse optional body `{ photo_ids?: string[], draft?: boolean }`
8. `new PoshmarkAdapter(creds)` → `publishListingToPoshmark(...)`
9. Returns `{ ok: true, platformId?, url?, draft }`

When `createListing` throws `PoshmarkCreatePendingError`, the route returns `{ ok: false, error: "poshmark_create_pending", message: "..." }` with HTTP 501.

**`PoshmarkCreatePendingError`** lives in `src/lib/platforms/errors.ts`:

```ts
export class PoshmarkCreatePendingError extends Error {
  constructor() {
    super(
      'Poshmark createListing is pending reverse-engineering of POST /vm-rest/posts. ' +
      'Add the implementation to @local/poshmark-seller-sdk once the endpoint is confirmed.'
    )
    this.name = 'PoshmarkCreatePendingError'
  }
}
```

## Out of Scope

- Photo upload to Poshmark CDN (SDK concern; `createListing` handles it internally once implemented)
- Actual `createListing` API call in the SDK (needs Charles Proxy reverse-engineering)
- Notifications, messaging, offers (separate feature, tracked separately)
- Auto-discount Inngest function for Poshmark (already works via the existing `updateListing`)
- UI changes (publish button, platform picker) — separate UI task
